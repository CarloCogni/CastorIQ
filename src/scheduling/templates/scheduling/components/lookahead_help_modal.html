How Time View Works

What is it?

Time View is a date-based 4D programme view for the linked model. It answers what was planned, what actually happened, and the accumulated model state at the selected Playback date. Modes: Planned, Actual, and Variance (default). Model colours use applied / confirmed links only. This is not a walkthrough, playlist of activities, or construction simulation.

Date truth

  • The primary label is Playback date · <selected timeline date> — the same date as the scrubber, the colour payload, and the model paints.
  • Secondary context shows Programme · start – finish.
  • Browser “today” is never used as the colour date.
  • First entry opens at programme start so the 4D sequence can be played. Refresh/return in the same session restores the last Playback date and mode.

Modes

  • Planned — approved programme only (not started muted grey / in progress / complete / insufficient purple). Never claims actual completion.
  • Actual — dated actual evidence only. Complete work is green even if it finished late against the plan. In progress is blue. Future-dated actuals stay muted grey (“No actual progress by this date”); absent Actual Start/Finish evidence is purple (“No actual dates recorded”). Never falls back to planned dates or variance wording.
  • Variance — plan vs actual at the playback date (completed by/after planned finish, in progress within/past planned finish, planned start/finish passed with no actual update, not yet due, incomplete schedule dates, no linked activity).
  • Changing mode keeps the Playback date and camera, pauses play if running, and recolours immediately.

Visible context

  • Future / not-due geometry stays visible as muted light grey by default so upper floors do not vanish.
  • Hide future work is optional in Settings; when off (default), context stays ghosted.
  • Unlinked elements stay No linked schedule activity wireframe.
  • The comparison strip (all modes) reports element-set counts at the Playback date: Planned complete, Actual complete, Plan-complete but not actual-complete, No actual evidence.

Programme Playback controls

  • Time View always opens Paused. The timeline never advances until you press Play.
  • Playback date opens a real calendar. Choosing a date pauses playback and locks that date until you Play or change it again.
  • View Planned / Actual / Variance are real buttons in the dock — one click switches mode, pauses playback, and keeps the same date.
  • Transport order: Start · Previous · Play/Pause · Next · End. Previous/Next and Play traverse unique linked activity dates (not individual lifecycle records). Several activities on one date appear together.
  • The right panel follows the selected mode on the exact selected day: Planned shows Planned at this date membership only, Actual shows Actual at this date only, and Variance shows exclusive Planned + Actual / Planned only / Actual only groups. Play / Prev / Next traverse that mode’s linked-date queue.
  • Dragging the slider pauses immediately; release renders that date and stays paused.
  • Full playback is the presentation duration for a complete play-through across unique dates.

Who can do what

Any project member with schedule access can view Time View and programme playback. Creating or editing task-to-model links requires modify access on Links.

Caveats

This is a read-only playback view — no links are created here. Actual mode does not invent history from status or percent-complete fields. Variance does not invent percentage “ahead” without time-phased progress evidence. Interval step is weekly in this release. Package-linked colouring means one activity can paint many elements with the same state.
