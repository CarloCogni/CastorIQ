How Link Governance Work

What is it?

Workspace separating trusted accepted bindings, active review suggestions, property hints, legacy M2M compatibility, and deterministic possible conflicts under policies trusted-binding-v1 and governance-authority-v1.

Trusted vs review vs inactive

Trusted requires is_active, governance_status=trusted, and needs_review=false. Active review requires active_review and needs_review=true. Rejected, reversed, and superseded bindings are inactive — excluded from Gantt, viewer, EVM, and overview trusted reads. Confidence never grants trust.

Decisions and lifecycle

Approve individual (editor+), bulk approve (owner+), reject, reaffirm, reverse, supersede, and parity repair each require explicit authority and create append-only audit events after migration 0024. Pre-audit trusted rows have no retrospective events.

Who can do what

  • Viewer — overview, queue, reconciliation shell, audit read
  • Editor — approve one, reject, reaffirm, M2M add parity
  • Owner — bulk approve, exact preview, reverse, supersede, M2M remove parity

Caveats

Property Activity ID is evidence only — not a trusted binding. Reconciliation is diagnostic — run explicitly; not evaluated on overview load. Task coverage denominator is all schedule activities, not physical-scope 4D completeness. Multiple trusted tasks on one entity are allowed unless overlap evidence triggers conflict acknowledgment.
