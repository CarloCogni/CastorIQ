How Link Governance Work
What is it?

Workspace separating trusted accepted bindings, review suggestions, property hints, legacy M2M compatibility, and deterministic possible conflicts under policy trusted-binding-v1.

Trusted vs review

Trusted means needs_review=False. Review suggestions never drive colormap, readiness, or viewer highlights until explicitly approved. Property Activity ID metadata is evidence only.

How to approve (E2-C)

In Review mode, use Approve on one row or select up to 100 items for bulk preview. Exact literal full-preview uses the separate E1 flow (Activity ID parameter match). Normalized, heuristic, and semantic suggestions require explicit human approval — confidence never auto-trusts.

Defer and reject

Defer closes the panel with no database change. Persistent rejection history and reversal arrive in E2-E — there is no reject button in E2-C.

Who can approve

Project editors and owners with link-management modify permission. Viewers can browse the queue but cannot approve.

Reconciliation (E2-D)

The Reconciliation tab runs a read-only diagnostic over bindings, evidence drift, M2M parity, and multi-task conflicts. No links are changed — remediation is preview-only until E2-E.

Caveats

Multiple accepted tasks on one entity are allowed unless overlap evidence triggers a possible conflict requiring acknowledgment. Legacy M2M rows without accepted bindings are compatibility storage only. Decision references in responses are operational — not immutable audit records.
