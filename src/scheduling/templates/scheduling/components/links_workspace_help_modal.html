How Links Works

What is it?

Links is a parameter / rule-based schedule–model linking workspace. You configure a Link Rule (schedule field ↔ model parameter), run a read-only Link Check, review Match Results, then apply matches only with an explicit action. Model Context stays central for visual confirmation.

Lifecycle

  1. Set a Link Rule — schedule field (Activity Code) and model parameter name.
  2. Run Link Check — dry-run / preview only; no links are written.
  3. Review Match Results — Matched, Unmatched Activities, Unmatched Model Elements, Conflicts.
  4. Use Apply Links only when you intend to persist exact preview matches.
  5. Use Manual fallback only for individual exceptions.

How to run a Link Check

  • Enter the IFC / Revit property that holds the activity code (e.g. Activity ID).
  • Match type is exact equality for this version.
  • Results are preview status until Apply Links (or Manual fallback) is used.

Who can do what

Any member with schedule access can run Link Check (read-only). Apply Links and Manual fallback require modify / link permission on the project.

Caveats

Matching is rule-based and deterministic only. Contains / fuzzy matching and full model parameter catalogs are not available yet. Link Check never creates bindings by itself. Schedule writeback is not available here.
