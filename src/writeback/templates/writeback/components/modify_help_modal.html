How Modify works

What is Modify?

Modify changes the IFC model from a sentence. Castor writes the change as a small piece of IfcOpenShell code, runs it on a copy of the file, and shows you what actually changed before anything touches the real file. Every approved change becomes a git commit you can restore from the History tab.

How a request flows

groundCastor reads the storeys, spaces, entity counts and property sets of the file from the database. No model call.
generateThe Modify model writes two functions: select picks the target entities, modify changes them.
runA separate process runs the code on a scratch copy and measures the before/after difference.
verifyAnything changed outside the selection, or any geometry, sends the code back for a repair (at most two). Every diff row is then compared with your request: a value or a property name your request never mentions is flagged. A second model then explains the change from the code and the diff without seeing your request.
guardianThe project documents are searched for anything that confirms or contradicts the change. Advisory only.
approveThe reviewed copy replaces the original, the change is committed to git with the code in the commit, and the index is refreshed. The code never runs a second time.

How to review a proposal

Your request is repeated at the top of the card. The sentence under it was written from the code and the diff, not from your request. If it does not say what you asked for, reject.
Targets are listed by name, type, container and one property, straight from the index, so you can see the selection is the right one.
Diff rows aggregate the change: FireRating: (none) → EI60 × 5 means five entities got that value.
Flagged rows sit on top in a warning colour. A row is flagged when something about it is not in your request: its new value (value not in request), the property it changed (property not in request, for example a U-value written when you asked for a fire rating), or an entity created or deleted. Tick each one to enable Approve. Normal rows need nothing. The model is shown, per property set, the standard properties the file does not hold yet, so a request for a missing property adds it instead of reusing a neighbour.
Guardian shows whether the documents confirm, contradict, or say nothing. Untick Check documents next to the input to skip it when you know the documents are silent; the skip is recorded on the proposal.
The code is one click away, collapsed. You do not have to read Python to approve.

Who can do what

  • Editors and owners can propose, approve and reject.
  • Viewers can read this tab and the History tab but cannot propose, approve or reject.
  • Sending a new request supersedes any proposal still pending in the same conversation.

Caveats

Geometry is out of scope: moving, resizing or reshaping anything is refused, never proposed. If the file changes between proposal and approval, approval is refused with "file changed, please re-propose". One file per request. Several changes in one sentence are fine and become one commit. Approval refreshes the index for the changed entities but does not re-embed them for Ask until the file is reprocessed; a created storey or space appears as an entity but not in the spatial tree until then. Pressing Stop, or closing the tab, discards the run in progress: no proposal is left pending and the scratch copy is deleted. If the Modify model does not answer in time or cannot be reached, the request ends with a retryable failure card; nothing is written. Use the storey, space and property-set names as they appear in the model; Castor lists them for the model, it does not guess.

Which model runs Modify

Graphics memoryModify modelNote
8 GB7B coderthe floor; measured in the benchmark, not assumed
12 GB14B coderthe default, settled by the benchmark bake-off
24 GB30B coderbest local quality

All inference is local. A model that does not fit in graphics memory is not spilled into system memory: that turns a thirty-second generation into minutes. The explanation sentence is written by the same Modify model.

Tips

  • Use storey, space and property-set names as they appear in the model.
  • Name the type: say walls or doors, not "elements".
  • Write the exact value you want: a value that does not appear in your request is flagged on the card.
