Why did this modification fail?

Castor writes every change as a small piece of code, runs it on a copy of the file, and checks what the code did before you see anything. When a run fails a check, the model gets the error back and tries again, at most twice. After a third failure the request is rejected with the last error, so a wrong change never reaches the file.

What the failure types mean
Target Not Found

The code's select() returned no entities three times. Usually a storey, space or property-set name that does not exist in this file. Fix: use the names as they appear in the model (the Explore tab lists them), e.g. "walls on Ground Floor" rather than "walls on level 1".

Scope Violation

The code changed entities outside the ones it selected, or touched geometry. The diff is the gate: such a change is never proposed. Fix: name the targets more precisely; geometry changes are out of scope by design.

Code Execution Error / Code Missing Entrypoint

The generated code raised an error, or the model answered in prose instead of code. Both are fed back for a repair. If it still fails, fix: put the verb and value first, then the target ("Set FireRating to EI60 on the walls on Ground Floor").

Stale Proposal

The IFC file changed between the proposal and your approval, so the reviewed copy no longer applies. Fix: ask again; the new proposal is built against the current file.

No Change

The right entities were selected but they already have the requested values. Nothing to approve.

Model size matters

Modify uses a code-tuned local model sized to your graphics memory: a 7B coder on 8 GB, a 14B coder on 12 GB, a 30B coder on 24 GB. The smaller the model, the more often a request needs a repair round or is rejected. The benchmark records in docs/evaluation/ give the measured rates per model.

If the same prompt keeps failing
  1. Use the exact storey, space and property-set names from the model.
  2. Rephrase: verb and value first, then the target.
  3. Split a long sentence into one change per request if the repairs keep landing on different parts of it.
