How Schema Quantity Insight Works

What is it?

A read-only report over a frozen 5D preparation snapshot (F2). It groups IFC quantity rows by project schema classification, package, and work package using C3 provenance when present, and shows unmapped rows and basis/source gaps honestly.

Lifecycle

Quantities preparation → optional schema-backed session mapping → freeze F2 snapshot → open this report (S2 insight service). The report does not rebuild Quantities runtime and does not mutate the snapshot.

How to use it

  • Read snapshot summary and boundary badges first.
  • Review classification and package rollups (equal primary groupings).
  • Check work package rollup — it may be mostly Unmapped.
  • Use gaps and issue sample to see what still needs mapping or basis setup.
  • Return to Quantities to adjust session mapping, then freeze a new version.

Who can do what

Any project member with read access can open the report. Mapping happens in Quantities (session). Snapshot creation is a separate action. This page never writes.

Caveats

  • Session schema mapping is not an approved official assignment.
  • Demo schemas are internal vocabularies, not certified standards.
  • Mixed quantity bases and units are never coerced into one total.
  • Excel / Ask import into schema is not connected yet.

Not claimed

Not BOQ. Not QS certified. Not cost estimate. Not rate calculation. Not EVM. Not schedule cost loading. Not writeback. Not approval.
