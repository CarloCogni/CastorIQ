How Quantities Works

What is it?

Quantities opens on one quantity table built from indexed IFC (openBIM-first). Use Columns, Filter, Set measurement, Assign values, Units, Save table, Open table, Save version, and Export table from the primary toolbar. There is no six-stage Discover→Configure→Map→Units→Freeze→Review rail. Advanced & reference keeps configure/schema tools available when needed. Help covers boundaries (not Ask, Modify, BOQ, cost, or writeback).

Some fields are exported by the authoring tool into the IFC file, such as Family, Type, Category, Workset, OmniClass, or Assembly Code. Castor treats them as model evidence, not as Revit-only assumptions. Availability varies by export.

IFC Classification References are native IFC relationships. They are separate from authoring properties and separate from Castor schema mapping.

Zone is not found in this IFC export when readiness shows Missing in this IFC export. Another IFC export may include zone membership, or the user may choose a zone source from available properties.

Lifecycle

After an IFC file is indexed, this page reads entity properties at runtime. Current edits to schema include/exclude, source-type mapping intent, and measurement rules are session-only (GET query params) until you save a named preparation configuration draft. A saved draft stores settings only: basis rules, schema includes, and source mapping intent — not generated quantity rows, totals, register counts, visuals, or row reviews. It does not approve, certify, write back, or create BOQ/cost. Row reviews (status + note) are session-only until you use Save table, which keeps editable work across logout and restart. Ending the browser session without Save table may clear row reviews. Save version creates a read-only copy; it does not replace Save table. Preparation configuration drafts remain settings-only (basis/schema/source intent). Refresh without parameters restores defaults unless a prep_config draft or saved table is loaded. Generate may continue as session GET params after a draft is loaded. Required/core fields are locked. Excluded optional fields are omitted from the generated table and are not counted as unresolved schema gaps. Source Mapping edits classification / package / work-package source type only — no values are created, no property picker. Sending unresolved rows to Castor Modify is disabled here — Modify owns suggest / review / approve / writeback / Git trace / re-index.

How to use it

  • Quantity table — Class → Type → Instance. Classes start collapsed. “Expand classes” reveals Types only; expand a Type for elements. Collapse a Class resets its Type expansion. Parent quantities always cover all matching descendants.
  • Add column — one searchable catalogue (table fields, assigned values, and indexed IFC Element/Type/Qto/Spatial/Classification fields). Search first; Add is disabled until a selection. Calculation (Sum / Average / Min / Max) applies to eligible numeric columns on Class/Type parents from matching instance leaves.
  • Type identity follows IFC type GlobalId (IfcRelDefinesByType). Distinct GlobalIds that share a display name stay separate — full GlobalId is in Row details.
  • Set measurement / Assign values — parent selection targets descendant elements (deduplicated). Assign values is session-only and does not write back to IFC.
  • Units — convert displayed Quantity from model units; raw model values stay available for export.
  • Save table — durable editable work for this project (name required). Open table resumes it.
  • Save version — creates a read-only snapshot; editing continues afterward. Open Saved versions from the status chip.
  • Export table — ZIP of the current working table (model + output values).
  • Advanced & reference — optional configure/schema/source/rules and legacy export.
  • IFC columns — add IFC properties, model location, classification references, and exported properties; separate from Castor schema Assign values.
  • Semantic source readiness — frozen with each saved version and shown in 5D Quantity Review. Missing evidence means not found in this IFC export — not unsupported forever.
  • Unresolved Data Register — counts only included schema gaps for counting source intents; no fake readiness percentages. Session row reviews do not change these counts. Session manual mapping values may clear mapping gaps for that row only.
  • Preparation Data Model Visual Summary — count charts from generated rows only (Advanced).
  • Quantity Preparation Insights — deterministic operational notes (not AI).
  • Raw Indexed Quantity Inventory — input evidence only, under Advanced.

Who can do what

BIM coordinators and quantity reviewers use this page for preparation. Schedule link confirm / ignore stays under Links. IFC enrichment stays under Modify when enabled. Model link diagnostics stay under Model.

Caveats

  • No rule = unresolved. No selected basis = no measurement claim.
  • IfcWall and IfcSlab stay Unresolved until the user selects a basis and generates.
  • Current configuration edits are session-only until saved as a preparation configuration draft.
  • Saved drafts store preparation settings only — not generated quantity rows, not row reviews, and not manual mapping values.
  • Session row reviews do not approve, certify, write back, or generate BOQ.
  • Session manual mapping values are available only for included fields configured as Manual field — session-only annotations.
  • Schema-backed node selections (when a project schema is adopted) are session annotations only — they do not create ClassificationAssignment records, are not approved/certified classifications, and do not write back to IFC. Export schema metadata support comes later (C3c).
  • Session row reviews do not resolve missing basis, quantity source, or mapping gaps.
  • Excluded fields are not counted as unresolved schema gaps.
  • Not mapped means intentional blank — not counted as missing.
  • Future Modify handoff / Manual field count as unresolved mapping gaps until a session value is entered.
  • Package Mapping is preparation grouping — this screen does not generate BOQ or cost output.
  • Send unresolved rows to Castor Modify is disabled in this slice.
  • Advanced tools “Export legacy QTO cache” dumps the optional legacy QTO cache only (may include cost/cache fields if present). It does not export the generated preparation data model, schema, source intent, row reviews, or manual mapping values. Prefer Export preparation model (session) on the Generated Preparation Data Model for the current preparation snapshot.
  • Quantity units — convert displayed output units in the Units panel. Session-only until Save version; raw model values remain for export.
  • Measurement settings Output unit follows the selected measurement: Count is read-only (no conversion); Length/Area/Volume options refresh to that family. A mismatched output unit is rejected on Apply.
  • Total Quantity, Unit, and Measurement Basis stay separate columns — never number+unit in one field.
  • Volume / area / length stay “Unit not resolved” until confirmed — Castor does not invent SI labels from quantity basis names.
  • Hub ?tab=quantities on scheduling does not render this page — use the Quantities hub link.
